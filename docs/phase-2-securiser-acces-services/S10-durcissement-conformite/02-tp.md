## Contraintes

- Une machine virtuelle **Debian** avec un compte `sudo` (celle des séances précédentes convient : **ne pas** reprendre une machine déjà durcie si tu veux voir des écarts). **Instantané** avant de commencer.
- Paquet `lynis`. L'audit est **local** (il n'envoie rien) et **ne modifie rien** : il lit la configuration.
- Tu **notes la sortie** de chaque commande (capture d'écran datée).

## Partie B – La mesure de départ (≈ 40 min)

### B1 – Installer et lancer l'audit

```bash
sudo apt install -y lynis
sudo lynis audit system --quick --no-colors
```

L'option `--quick` évite les pauses à chaque section. L'audit dure environ une minute ou deux.

### B2 – Lire le résultat

À la fin, l'outil affiche un résumé. Relève aussi les chiffres dans le rapport :

```bash
sudo grep -E '^(hardening_index|lynis_version)' /var/log/lynis-report.dat
sudo grep -c '^warning\[\]' /var/log/lynis-report.dat
sudo grep -c '^suggestion\[\]' /var/log/lynis-report.dat
```

| Mesure | Valeur de départ |
|---|---|
| Indice de durcissement | |
| Nombre d'avertissements | |
| Nombre de suggestions | |

### B3 – Lister les avertissements et les suggestions

```bash
sudo grep '^warning\[\]' /var/log/lynis-report.dat | cut -d'|' -f1,2
sudo grep '^suggestion\[\]' /var/log/lynis-report.dat | cut -d'|' -f1,2 | head -30
```

**Je comprends.** Chaque ligne commence par un **identifiant de test** (par exemple `AUTH-9328`). Pour comprendre un test, demande le **détail** : `sudo lynis show details AUTH-9328`.

**Point de contrôle :** capture des valeurs de B2 et de la liste des avertissements.

## Partie D – Corriger (≈ 50 min)

Applique au moins **trois** corrections parmi celles de la liste ci-dessous (celles **présentes** dans ton rapport), ou d'autres de ton tri. Pour chacune, note la commande et le test.

### D1 – Droits par défaut des nouveaux fichiers (si la suggestion « Default umask » est présente)

```bash
sudo grep -E '^UMASK' /etc/login.defs
sudo sed -i 's/^UMASK.*/UMASK           027/' /etc/login.defs
sudo grep -E '^UMASK' /etc/login.defs
```

**Je comprends.** `027` : les nouveaux fichiers ne sont **ni lisibles ni modifiables par les « autres »**. L'effet s'applique aux **nouvelles** sessions.

### D2 – Âge des mots de passe (si les suggestions sur l'âge minimal et maximal sont présentes)

```bash
sudo sed -i 's/^PASS_MAX_DAYS.*/PASS_MAX_DAYS   90/; s/^PASS_MIN_DAYS.*/PASS_MIN_DAYS   1/' /etc/login.defs
sudo grep -E '^PASS_(MAX|MIN)_DAYS' /etc/login.defs
```

> [!WARNING]
> Ces réglages **ne s'appliquent qu'aux comptes créés ensuite**. Pour un compte existant : `sudo chage -M 90 -m 1 NOM_DU_COMPTE`. Les durées sont des valeurs de **laboratoire** : la politique réelle se décide d'après la recommandation à jour (séance S06) et peut ne pas imposer de changement périodique.

### D3 – Outils de vérification et de suivi (si les suggestions « debsums » et « apt-show-versions » sont présentes)

```bash
sudo apt install -y debsums apt-show-versions
sudo debsums -s | head
```

**Je comprends.** `debsums -s` ne signale que les fichiers de paquets dont le **contenu a changé** par rapport au paquet d'origine : s'il affiche quelque chose, un fichier a été modifié (légitimement ou non). Aucun affichage = tout est conforme.
