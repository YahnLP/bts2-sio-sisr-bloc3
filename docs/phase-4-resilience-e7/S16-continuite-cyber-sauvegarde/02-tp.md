## Le laboratoire

Une **machine virtuelle Debian** avec un compte `sudo`. Elle joue **deux rôles** grâce à deux comptes :

| Compte | Rôle | Droits |
|---|---|---|
| `prod` | Le serveur de production, **qui sera « compromis »** | Propriétaire des données |
| `sauve` | Le serveur de sauvegarde | Propriétaire du dépôt de sauvegarde, lit les données |

> [!NOTE]
> Une seule machine suffit pour **voir le principe** (séparation des comptes). En réalité, le serveur de sauvegarde est une **autre machine**, idéalement hors de l'annuaire de production : un attaquant **administrateur** de la machine ici (`root`) pourrait tout effacer. Cette limite est le sujet de la partie G.

**Contraintes.** **Instantané** de la machine avant de commencer ; paquet `restic` ; tu **notes la sortie** de chaque commande (capture datée). Le **mot de passe du dépôt** utilisé ici (`Mdp-Depot-Lab-1`) est un mot de passe de **laboratoire**.

## Partie B – Préparer le laboratoire (≈ 20 min)

```bash
sudo apt install -y restic
sudo useradd -m -s /bin/bash prod
sudo useradd -m -s /bin/bash sauve
sudo mkdir -p /srv/donnees/Plans /srv/donnees/Compta
for i in $(seq 1 20); do sudo head -c 300000 /dev/urandom | sudo tee /srv/donnees/Plans/plan$i.dwg >/dev/null; done
for i in $(seq 1 10); do echo "ecriture $i" | sudo tee /srv/donnees/Compta/piece$i.txt >/dev/null; done
sudo chown -R prod:sauve /srv/donnees
sudo chmod -R 750 /srv/donnees
sudo install -d -o sauve -g sauve -m 700 /srv/sauvegarde
```

**Je comprends.** Que signifient les droits `750` sur les données et `700` sur `/srv/sauvegarde` ? Qui peut lire les données ? Qui peut lire la sauvegarde ? ______________________

## Partie C – Une sauvegarde avec versions (≈ 30 min)

Les commandes de sauvegarde s'exécutent **en tant que `sauve`** (le serveur de sauvegarde « tire » les données).

```bash
sudo su - sauve
export RESTIC_PASSWORD="Mdp-Depot-Lab-1"
restic init -r /srv/sauvegarde/depot
restic backup -r /srv/sauvegarde/depot /srv/donnees
exit
```

Modifie ensuite une pièce comptable, puis refais une sauvegarde :

```bash
echo "correction" | sudo tee -a /srv/donnees/Compta/piece1.txt
sudo su - sauve
export RESTIC_PASSWORD="Mdp-Depot-Lab-1"
restic backup -r /srv/sauvegarde/depot /srv/donnees
restic snapshots -r /srv/sauvegarde/depot
exit
```

**J'anticipe.** Combien de **versions** (instantanés) verras-tu ? La deuxième sauvegarde sera-t-elle aussi volumineuse que la première ? ______________________

**Je comprends.** Qu'apporte la conservation de **plusieurs versions** face à un rançongiciel ? Quel paramètre détermine « jusqu'où on peut remonter » ? ______________________

Prends maintenant le **manifeste** (liste des empreintes) de l'état sauvegardé, pour pouvoir **prouver** la restauration :

```bash
sudo find /srv/donnees -type f | sort | sudo xargs sha256sum | sudo tee /root/manifeste.sha256 | wc -l
```

### Vérifier l'intégrité

```bash
sudo su - sauve
export RESTIC_PASSWORD="Mdp-Depot-Lab-1"
restic check -r /srv/sauvegarde/depot
restic forget -r /srv/sauvegarde/depot --keep-last 1 --dry-run
exit
```

L'option `--dry-run` **simule** la suppression des anciennes versions sans rien supprimer.

**Point de contrôle :** capture des deux instantanés, du nombre de lignes du manifeste, de `restic check`.

### D2 – Le sinistre

Le compte `prod` est « compromis » : l'attaquant a ses droits. Simule son action (**uniquement dans le laboratoire**) :

```bash

```

## Partie E – Restaurer en chronométrant (≈ 30 min)

```bash
sudo mkdir /srv/restauration
sudo chown sauve /srv/restauration
sudo su - sauve
export RESTIC_PASSWORD="Mdp-Depot-Lab-1"
time restic restore latest -r /srv/sauvegarde/depot --target /srv/restauration
exit
```

Vérifie que ce qui est restauré est **identique** à l'état d'avant le sinistre :

```bash
cd /srv/restauration
sudo sed 's#/srv/donnees#/srv/restauration/srv/donnees#' /root/manifeste.sha256 | sudo sha256sum -c 2>&1 | grep -vc ': OK'
```

Le chiffre affiché est le nombre de fichiers **non conformes** : il doit valoir **0**.

| Mesure | Valeur |
|---|---|
| Volume restauré | |
| Durée mesurée (`real`) | |
| Débit (volume ÷ durée) | |
| Fichiers non conformes | |

**Je comprends.** Pourquoi la vérification par **empreinte** est-elle plus fiable que « j'ouvre quelques fichiers » ? Que faut-il faire **avant** de remettre ces données en service sur la production (séance S15) ? ______________________

## Partie G – Aller plus loin : la copie scellée et ses limites (≈ 20 min)

```bash
sudo tar -C /srv -cf /srv/sauvegarde/scelle.tar restauration
sudo chown sauve /srv/sauvegarde/scelle.tar
sudo chattr +i /srv/sauvegarde/scelle.tar
sudo su - sauve -c 'rm -f /srv/sauvegarde/scelle.tar'
lsattr /srv/sauvegarde/scelle.tar
sudo chattr -i /srv/sauvegarde/scelle.tar
```

L'attribut `+i` rend le fichier **immuable** : même son propriétaire ne peut ni le supprimer ni le modifier.
