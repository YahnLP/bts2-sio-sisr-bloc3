## Partie B – Le collecteur (≈ 35 min)

Sur `coll` :

### B1 – Un dossier réservé

```bash
sudo install -d -o syslog -g adm -m 750 /var/log/central
```

**Je comprends.** Le service `rsyslog` s'exécute sous l'utilisateur `syslog`, pas `root`. Que se passerait-il si le dossier appartenait à `root` ? (Tu peux le vérifier : c'est l'erreur la plus fréquente de ce TP.) ______________________

### B2 – La configuration de réception

Crée `/etc/rsyslog.d/10-collecteur.conf` (avec `sudo nano`) :

```text
# Reception des journaux des autres machines (TCP 514, reseau de laboratoire uniquement)
module(load="imtcp")
input(type="imtcp" port="514")

# Un dossier par machine, un fichier par programme
template(name="ParMachine" type="string" string="/var/log/central/%HOSTNAME%/%programname%.log")

# Format du fichier d'alertes : date, machine, message
template(name="Alerte" type="string" string="%timegenerated:::date-rfc3339% %HOSTNAME% %msg%\n")

# Les echecs de connexion sont copies dans un fichier dedie
if $msg contains "Failed password" then {
    action(type="omfile" file="/var/log/central/echecs-connexion.log" template="Alerte")
}

# Tout ce qui vient du reseau est range par machine, puis ne va pas plus loin
if $fromhost-ip != "127.0.0.1" then {
    action(type="omfile" dynaFile="ParMachine")
    stop
}
```

```bash
sudo rsyslogd -N1
sudo systemctl restart rsyslog
ss -ltn | grep 514
```

`rsyslogd -N1` **vérifie** la syntaxe sans rien lancer. Une ligne `LISTEN` sur le port 514 confirme la réception.

**Je comprends.** Explique chaque bloc de la configuration en une phrase. Pourquoi la dernière règle contient-elle `stop` ? ______________________

> [!WARNING]
> Le port 514 en **clair** convient à un laboratoire isolé. En production, on **chiffre** (TLS) et on **filtre** (pare-feu, séance S05) pour que seules les sources connues puissent écrire sur le collecteur : sinon n'importe qui peut **polluer** les journaux avec de faux événements.

**Point de contrôle :** capture du fichier de configuration et de la ligne `LISTEN`.

## Partie D – Corréler (≈ 40 min)

### D1 – Une règle de seuil, tous serveurs confondus

Sur `coll`, crée `~/correle.sh` :

```bash
#!/bin/sh
# Alerte si une meme adresse source cumule au moins SEUIL echecs, tous serveurs confondus
SEUIL=${1:-5}
sudo cat /var/log/central/echecs-connexion.log \
 | awk -v s="$SEUIL" '{ for(i=1;i<=NF;i++) if($i=="from"){ip=$(i+1); n[ip]++; h[ip" "$2]=1} }
   END{ for(ip in n) if(n[ip]>=s){ c=0; for(k in h){split(k,a," "); if(a[1]==ip)c++}; print "ALERTE: "ip" : "n[ip]" echecs sur "c" serveur(s)" } }'
```

```bash
chmod +x ~/correle.sh
~/correle.sh 5
~/correle.sh 10
```

## Partie F – Conserver (≈ 25 min)

### F1 – Rotation

Sur `coll`, crée `/etc/logrotate.d/central` :

```text
/var/log/central/*.log /var/log/central/*/*.log {
    daily
    rotate 180
    compress
    delaycompress
    missingok
    notifempty
    create 0640 syslog adm
    sharedscripts
    postrotate
        /usr/lib/rsyslog/rsyslog-rotate
    endscript
}
```

```bash
sudo logrotate -d /etc/logrotate.d/central
```

L'option `-d` **simule** sans rien modifier.
